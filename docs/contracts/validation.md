# 검증 결과

> [서비스 소개](../../README.md) · [차량 앱 동작](car-app.md) · [개발·실행 안내](development.md)

2026-11-03 기준, Pleos Connect Emulator 2.1.0의 차량 앱을 실제 배포 API·관리자 대시보드에 연결해 확인했습니다. 차량 앱은 ADB·uiautomator, 대시보드는 Orca 브라우저 UI로 조작했습니다. 운행을 서버에 직접 생성하지 않고 기어·계기판 변화로 기록했습니다.

## 서비스 흐름 검증

| 확인 항목 | 결과 |
| --- | --- |
| 최초 등록 | 직원·차량 등록 → 앱 권한 → 6자리 코드 → 관리자 페어링 → 차량 정보 수신 |
| 운전자 동의 | 이용자 선택·동의·집 등록, 동의 기록 서버 전송 |
| 자동 운행 | D에서 시작, 계기판 증가, P 유지 후 도착 질문 |
| 음성 확인 | PCM '네, 맞아요'를 Pleos STT로 인식해 업무·음성 확인으로 저장 |
| 미확인 처리 | 무응답 저장, 집·미등록 장소와 세부 시각 비공개 |
| 차량 수정 | 앱에서 업무 선택 후 서버 수정 이력·대시보드 반영 |
| 관리자 수정 | 사유와 함께 출퇴근으로 확정, 앱 동기화 후 미확인 목록에서 제거 |
| 개인 운행 | 관리자 목록·상세에서 장소·시각·메모 비공개, 관리자 수정 차단 |
| 오프라인 | 네트워크 없는 상태에서 기록 보존, 업데이트·환경 복구 후 전송 |
| 집계·내보내기 | 월간 집계·앱 CSV·대시보드 XLSX의 거리와 건수 대조 |

테스트 차량의 운행 **5건·34.5km**가 앱과 운영 목록에서 같은 UUID로 확인됐으며, 중복·미전송·실패는 없었습니다. 업무용 사용거리는 **26.5km**, 업무사용비율은 **76.8%**였습니다. CSV는 UTF-8 BOM·14열·5개 운행, XLSX는 5개 운행과 합계를 확인했습니다.

소수 거리에서 앱 목록과 서버의 반올림 차이를 발견해 계기판 양끝을 먼저 반올림하는 동일 기준으로 수정했고, 저장된 같은 운행에서 표시가 일치하는지 다시 확인했습니다.

## 확인 범위와 남은 검증

- **실제 마이크:** PCM을 실제 Pleos STT에 입력해 음성 흐름을 검증했습니다. 사람이 마이크에 말하는 입력 경로는 미확인입니다.
- **음성 엔진:** 이전 AVD 실측에서 STT 오류·네이티브 크래시가 발생했습니다. 답변을 잃으면 미확인으로 보존합니다. 오류 콜백 후 한 번 재질문은 단위 테스트로 검증했고 AVD 재현은 추가 확인이 필요합니다.
- **AVD 통신 복구:** 데이터를 다시 켜도 모뎀이 재연결되지 않아 AVD 재기동과 같은 APK의 `-r` 재설치 후 전송을 확인했습니다. 페어링·동의·대기 기록은 유지됐습니다. 통신망 토글만으로 복구되거나 재설치 없이 재부팅되는 경로를 검증한 것은 아닙니다.
- **대시보드 갱신:** 새 기록은 화면 재진입·새로고침으로 확인했습니다. 실시간 자동 갱신은 현재 제공하지 않습니다.
- **제출 빌드:** 운영 연동은 `remoteDebug`로 검증했습니다. release 서명·제출 파일과 실차 동작은 별도 확인 대상입니다.
