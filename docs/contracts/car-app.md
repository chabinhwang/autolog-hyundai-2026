# 차량 앱 동작

> [기술 문서 목차](README.md) · [전체 구조](architecture.md) · [검증 결과](validation.md)

Pleos Connect 차량에서 운행 감지·용도 확인·로컬 저장·서버 동기화를 수행합니다. 화면은 정차 중에 사용하며 주행 중 화면 제한은 플랫폼 정책을 따릅니다.

## 1. 기록·복구·수정

- 기어 D/R에서 기록을 시작하고 P 유지 후 종료합니다. 잠깐 정차한 뒤 다시 출발하면 같은 운행으로 이어집니다. 화면의 운행 시작·종료 버튼으로 수동 기록도 가능합니다.
- 진행 중 시작 값은 DataStore에 보관해 서비스 재시작 후 복원합니다. 완료 운행의 좌표는 장소 판정 후 버리고, 장소명·유형과 계기판·시각을 Room에 저장합니다.
- 종료 시 미확인·답변 대기로 먼저 저장하고 용도 확인 뒤 전송합니다. 질문 중 앱이 꺼지면 다음 실행 때 미확인으로 전송합니다.
- 늦게 복원한 운행에는 즉시 도착 질문을 하지 않습니다. 다음 정차 시 24시간 안의 최근 미확인 운행을 한 번 다시 확인합니다.
- 0.5km 미만 운행은 직전 미전송 운행에 병합합니다. 직전 운행이 전송됐다면 새 짧은 운행을 기록하지 않습니다.
- 전송 전 수정은 로컬에 반영하고, 전송 후 수정은 서버 수정 이력으로 보냅니다. 운행마다 기록 당시 차량 ID를 보관해 다른 차량 재등록 시 기록이 섞이지 않게 합니다.

## 2. 서비스·동기화

| 항목 | 동작 |
| --- | --- |
| 기록 서비스 | 앱 시작과 부팅 후 Foreground Service로 감지·복원 |
| 전송 순서 | 동의 기록 → 운행 → 수정 → 설정 내려받기 |
| 전송 시점 | 기록 저장·수정·앱 시작·주행 시작, 15분 주기 작업 |
| 즉시 작업 | WorkManager `REPLACE`로 백오프 중 이전 요청을 대체 |
| 네트워크·429·5xx | 기록 보존 후 재시도, 백오프 30초부터 시작 |
| 기기 토큰 401 | 업로드 중단·재등록 안내, 로컬 기록 유지 |
| 직원 없음 | 해당 운행의 이용자를 비우고 재전송 |
| 기타 건별 거절 | `FAILED`로 보관하고 '전송 실패 N건' 표시 |
| 관리자 수정 | `tripUpdates`로 수신해 앱 용도·미확인 목록에 반영 |

'동기화' 버튼은 30초에 한 번 즉시 요청할 수 있습니다. '모두 전송됨', '전송 대기 N건', '전송 실패 N건'으로 상태를 구분합니다.

## 3. 음성·용도 추정·주행 제한

- 등록한 집·회사·거래처와 서울 시간대로 용도를 추정합니다. 출근은 평일 06:00~10:59, 퇴근은 16:00~22:59이며 주말에는 출퇴근으로 추정하지 않습니다.
- 미등록 장소는 NaviHelper가 제공하는 주소의 동 이름을 사용합니다. 내비가 준비되지 않았거나 응답이 없으면 장소명을 비워 둡니다.
- 도착 질문은 음성과 팝업으로 함께 표시합니다. 음성·버튼 중 먼저 들어온 답을 사용하고, '나중에' 또는 무응답이면 미확인으로 남깁니다.
- 화면 선택은 `MANUAL`, 음성 확인은 `VOICE`입니다. 거래처 도착의 업무 선택은 `VISIT`, 그 외는 `OTHER`로 보냅니다.
- 용도를 고르면 5초 동안 '다시 선택'할 수 있습니다. 미확인 목록에서도 출퇴근·업무·개인을 선택할 수 있으며 도착 알림의 버튼으로도 답할 수 있습니다.
- 음성 인식은 완료·부분 결과를 모아 해석합니다. 결과 없는 오류 콜백에는 한 번 다시 묻고, 계속 실패하면 미확인으로 보존합니다. 응답 전체가 '너무'인 경우의 업무 보정은 문장 안의 같은 단어에는 적용하지 않습니다.
- 화면은 시스템 라이트·다크 모드를 따르고, 창 너비에 따라 한 단·두 단으로 배치합니다. 월간 요약과 최근·미확인 운행 목록을 표시합니다.

## 4. 권한·동의

차량 데이터·위치·내비·음성 서비스 권한과 Foreground Service 권한을 사용합니다. 위치·녹음·알림은 필요한 런타임 권한을 요청합니다. 실제 목록은 [AndroidManifest.xml](../../app/car/src/main/AndroidManifest.xml)을 따릅니다.

직원을 처음 이용자로 선택할 때 수집 항목·관리자 열람 범위·보유 기간을 안내하고 동의를 받습니다. 거부하면 해당 직원은 선택할 수 없습니다. 집 위치는 차량에만 저장합니다. 상세 정책은 [동의 규칙](rules.md#11-개인정보-보유삭제동의-d13)을 참고하세요.

## 5. 빌드·CSV

| 빌드 | API 호스트 | P 유지 종료 확정 | 용도 |
| --- | --- | --- | --- |
| release | `https://autolog-api.aihub.io.kr` | 180초 | 제출·일반 사용 |
| debug | `http://10.0.2.2:8080` | 30초 | 로컬 서버·SDK 점검 |
| remoteDebug | `https://autolog-api.aihub.io.kr` | 30초 | 배포 서버 연동 테스트 |

`remoteDebug`는 `com.autolog.app.remote`·'AutoLog 서버 테스트'로 별도 설치해 로컬 앱과 기록·토큰을 분리합니다. 설치 명령은 [개발·실행 안내](development.md)에 있습니다.

- 목록의 한 건 주행거리는 API·CSV와 같이 계기판 양끝을 각각 소수 첫째 자리로 반올림한 뒤 뺍니다. 예: `30019.25 → 30023.5`는 `4.2km`입니다. 원본 계기판 값은 유지합니다.
- 이번 달 요약은 총거리를 소수 둘째 자리까지, 업무사용비율을 `(출퇴근 + 업무) ÷ 총거리`로 표시합니다. 답변 대기 운행은 제외합니다.
- CSV는 UTF-8 BOM·14열이며 API 29 이상에서는 다운로드 폴더에 저장합니다. API 28은 앱 전용 다운로드 폴더를 사용합니다. 수식처럼 해석될 수 있는 문자열은 이스케이프합니다.
- 디버그 빌드의 `filesDir/voice_answer.pcm`은 실제 마이크 대신 한 번 사용하는 검증 입력입니다. 형식은 16kHz·16bit·mono이며 STT 오류 재질문에는 캐시한 입력을 다시 사용합니다.

## 6. 처음부터 끝까지 실측한 흐름

운영 서버 연결·수정·비공개 처리·오프라인 보존·내보내기 결과는 [검증 결과](validation.md)에서 한 번에 확인할 수 있습니다. 차량 앱 단위 테스트 122개와 remoteDebug 빌드·lint를 통과했습니다(2026-11-03).

## 7. 남은 항목

실제 마이크 입력과 일부 STT 복구 경로, AVD 통신 재연결은 추가 검증이 필요합니다. 문 열림에 따른 운행 종료와 동기화 후 90일이 지난 기록의 자동 삭제는 미구현입니다. 동의 화면에도 현재 체험판의 자동 삭제 미지원 상태를 안내합니다. 서명된 제출용 release와 P 유지 180초의 운영 연동 결과는 [검증 결과](validation.md#제출용-release-추가-확인)에 정리했습니다.
